# react-object-page

An open-core React design system built around two enterprise UI patterns: the **List Report** (a list
with filters and bulk actions) and the **Object Page** (a sectioned editor with an anchor bar, a sticky
save bar and a dirty-guard). Everything below is rendered by the library itself, not pasted as a
screenshot or a code snippet: try it.

## What makes it different

### 1. Two complete floorplans, not just widgets

A **List Report** with filter pills, search and sortable columns, in a layout that keeps the same
footprint while loading, empty or full. Click a column header, pick a filter, type in the search box.

### 2. Dirty-tracking you can trust

The Object Page form compares the values with the real saved baseline: editing a field marks the form
dirty, typing the original value back makes it clean again, and a value hydrated from outside is never
mistaken for a user gesture. Pair it with `useDirtyGuard` to protect exits and reloads.

### 3. Accessible by default, verified in CI

Keyboard, focus management and ARIA are part of every component, and the stories are covered by
Playwright end-to-end tests and by screenshot comparison (desktop, tablet and mobile viewports) in
continuous integration. Fields in a *locked*, *forced* or *disabled* state are not operable from the
keyboard, not just greyed out, and explain why through a real `aria-describedby`.

## Positioning: headless architecture, styled by default

react-object-page is headless the way the term is used throughout this project: the logic and state of every component — rendering, keyboard/focus behavior, the form state of the Object Page — live in hooks, decoupled from markup and from style. Headless here is about that separation, not about shipping zero CSS. On top of that architecture, components ship an opinionated, ready-to-use default style, so they look right out of the box once you import the stylesheet. The style is driven by design tokens exposed as plain CSS custom properties (`--color-rop-*`, `--text-rop-*`, `--radius-rop-*`, `--motion-rop-*`, ...): you re-theme the whole system, or one part of the page, by overriding those variables, without touching the source and without a JavaScript theme provider. (Overlays render in a portal outside your wrapper, so they take the page-level theme.)

<DemoFrame><ThemeOverrideDemo /></DemoFrame>

The full token list is in [Foundations: Tokens](?path=/docs/foundations-tokens--docs). Try it live in
[Foundations: Theming](?path=/story/foundations-theming--switcher): a switcher re-declares the
variables at runtime and the components follow. Hover, pressed and read-only shades are computed where
they are used, so they follow a base colour redeclared on any wrapper; that makes them optional
overrides with no value to read through a bare `var()` (see the package README).

It is an independent implementation of generic interaction patterns; it is not affiliated with, and
contains no code, asset or style from, any third-party design system.

- **`@react-object-page/core`**: MIT, free, on the public npm registry. Primitives and the simple
  versions of the two floorplans. This is what this Storybook documents.
- **`packages/pro`**: commercial add-ons that live in the same public monorepo.

Source and issues: [github.com/Utumno1984/react-object-page](https://github.com/Utumno1984/react-object-page).
Release notes: [GitHub releases](https://github.com/Utumno1984/react-object-page/releases)
(the per-package changelog is generated from the changesets in `.changeset/` at each release).

## Install

```bash
npm install @react-object-page/core
```

React 18 or 19 is required as a peer dependency.

## Use it

Import the stylesheet once, at the root of your app, then use the components:

```tsx
import '@react-object-page/core/styles.css';
import { Button, StatusBadge } from '@react-object-page/core';

export function Example() {
  return (
    <div style={{ display: 'flex', alignItems: 'center', gap: 12 }}>
      <StatusBadge tone="success">Approved</StatusBadge>
      <Button variant="primary" onClick={() => console.log('saved')}>
        Save
      </Button>
    </div>
  );
}
```

On a Tailwind v4 project you can import `@react-object-page/core/theme.css` instead, to get only the
design tokens (`--color-rop-*`, `--text-rop-*`, `--radius-rop-*`, `--motion-rop-*`, ...).

## How to read this Storybook

- Every component has a **Docs** page: description, the props table generated from the TypeScript
  types and their JSDoc, and a **Show code** snippet for each story.
- Stories marked with an **Interactions** panel run a scripted interaction (typing, clicking, opening an
  overlay) and assert the result, so they document a behaviour and prove it at the same time.
- Use the **Controls** panel to try the props live and the **Actions** panel to see the callbacks fire.
