# @react-object-page/core

React components and hooks for the **List Report** (filterable, sortable, selectable lists) and
**Object Page** (sectioned editor with anchor bar, sticky save bar and unsaved-changes guard)
interaction patterns, plus the primitives they are built from (`Button`, `Field`, `Input`, `Select`,
`Combobox`, `DatePicker`, `Dialog`, `Sheet`, `Tabs`, `Toast`...). Accessibility, keyboard support and
layout stability (no jumps between loading, empty and loaded states) are tested, not assumed.

This package is the free, MIT-licensed tier of the
[react-object-page](https://github.com/Utumno1984/react-object-page) project — see its
[**Stato**](https://github.com/Utumno1984/react-object-page#stato) section for what is in this
tier today versus the commercially-licensed `@react-object-page/pro`. It is an independent
implementation of generic, publicly known UI patterns.

**[Live demo and documentation (Storybook)](https://utumno1984.github.io/react-object-page/)**

## Install

```bash
npm install @react-object-page/core
```

Peer dependencies: `react` and `react-dom` (18 or 19).

## Quick start

```tsx
// once, at the root of your app (see "Styles" below for the Tailwind v4 alternative)
import '@react-object-page/core/styles.css';

import { Button, Field, Input } from '@react-object-page/core';

export function SupplierForm() {
  return (
    <form onSubmit={(event) => event.preventDefault()}>
      <Field label="Supplier name" name="supplier" help="As shown on the invoice." required>
        <Input defaultValue="Acme Ltd" />
      </Field>
      <Button type="submit" variant="primary">
        Save
      </Button>
    </form>
  );
}
```

`Field` wires the label, help text, error and required state to the control (real `aria-describedby`,
`aria-invalid`, `aria-required`). For whole pages see `ListReport`, `useListReport`, `ObjectPage`,
`useObjectPageForm` and `useDirtyGuard` in the Storybook above.

## Styles

The package ships design tokens (CSS variables in the `rop` namespace) and the utilities its
components use. There are **two alternative ways** to get them. Pick one.

### (a) Compiled stylesheet: any app

```ts
// once, at the root of your app
import '@react-object-page/core/styles.css';
```

`styles.css` contains no reset (no preflight, no rule on `html`, `body`, `*`, `button`...) and
every utility lives in a CSS `@layer`, so your own un-layered CSS always wins. It only contains
the utilities the library itself uses.

The layers are namespaced (`rop.theme`, `rop.utilities`) so they never merge with, nor reorder, the
layers of your app (`reset`, `base`, `components`, `utilities`...). Trade-off, accepted: the
library utilities are not part of your own `utilities` layer, so their precedence relative to your
layered CSS follows the order in which the layers first appear (import `styles.css` first and
your layers win; last and the library wins). Un-layered CSS always wins.

One exception to the namespacing: Tailwind v4 itself always emits a layer called `properties`
(`@layer properties`) for its internal `--tw-*` custom-property defaults. Its name is not under
our control, so `rop.*` cannot promise it away; what the library guarantees (and a test enforces)
is that it contains only inert `--tw-*` defaults (today: border style, line height, font weight)
and never the long list that `shadow-*`, `ring-*`, `translate-*` etc. would add. Components such as
`Button` therefore draw their focus indicator with a plain `outline`, not with those utilities.

### (b) Tailwind v4 project: tokens + sources

```css
@import 'tailwindcss';
@import '@react-object-page/core/theme.css';
/* path of the package's dist, relative to this CSS file */
@source '../node_modules/@react-object-page/core/dist';
```

In this mode the library utilities are generated by your own Tailwind build, into your own
`utilities` layer. They do not use the `rop.*` layers of (a), which is why the two modes must not
be mixed.

Do **not** also import `styles.css`: loading both duplicates the utilities and is unsupported
(it does not crash, but the output is redundant and the cascade order is not guaranteed).

`theme.css` only declares variables in the `rop` namespace (`--color-rop-*`, `--text-rop-*`,
`--font-rop-*`, `--radius-rop-*`, `--z-index-rop-*`, `--container-rop-*`, `--motion-rop-*`, `--animate-rop-*`); it never redefines Tailwind defaults. You
can use `text-rop-body`, `font-rop-mono`, `z-rop-modal`, `bg-rop-primary`... in your own markup.

### Tokens

| Group | Names |
|---|---|
| Colors | `text`, `text-muted`, `surface`, `surface-subtle`, `border`, `primary`, `primary-contrast`, `info`, `success`, `warning`, `error` |
| Derived colors (see below) | `primary-hover`, `primary-active`, `error-hover`, `error-active`, `surface-pressed`, `readonly-surface`, `readonly-indicator` |
| Type scale (size + line height) | `caption`, `body`, `label`, `title-sm`, `title-md`, `title-lg` |
| Families | `font-rop-sans`, `font-rop-mono` (system stacks, no web font; the mono stack ends with `monospace`) |
| z-index | `sticky` < `overlay` (backdrop) < `modal` < `popover` < `tooltip` |
| Motion | `--motion-rop-feedback-*` (a value that changed), `--motion-rop-overlay-duration` / `-easing` (`Dialog` / `Sheet` enter and exit, 160 ms). With `prefers-reduced-motion: reduce` there is no animation at all. The keyframes (`rop-*`) ship in `styles.css` / `theme.css`; without them the panel simply appears and disappears at once. The `--animate-rop-*` shorthands are resolved on `:root`: a duration or an easing redeclared on a wrapper does not reach them, override those on `:root` |
| Container query thresholds | `--container-rop-description-list` (24rem): the `DescriptionList` width from which `layout="auto"` is inline |

Tokens are plain CSS variables: override them in your own CSS for theming. **Exception: the
container query thresholds.** A container query condition cannot use `var()`, so Tailwind writes
the token's value into the compiled CSS: redefine `--container-rop-description-list` in the
`@theme` of your own Tailwind build (mode b, `theme.css`); overriding the variable at runtime or on
top of the precompiled `styles.css` (mode a) has no effect. Or force the layout with the `layout`
prop.

The derived colors are not fixed values: they are computed from a base color **on the element that
uses them**.

| Derived | Default |
|---|---|
| `primary-hover` / `primary-active` | `color-mix(in srgb, var(--color-rop-primary) 80%, black)` / `62%` |
| `error-hover` / `error-active` | `color-mix(in srgb, var(--color-rop-error) 80%, black)` / `62%` |
| `surface-pressed` | `color-mix(in srgb, var(--color-rop-surface-subtle) 96%, black)` |
| `readonly-surface` | `var(--color-rop-surface-subtle)` |
| `readonly-indicator` | `var(--color-rop-text-muted)` |

- **Override a base color at any scope** (`:root`, or a class on one part of the page): the hover,
  pressed and read-only shades inside it follow. Portaled content (`Select`, `Combobox`, `Menu`,
  `Dialog`, `Sheet`, `Tooltip`, `Toast`) renders outside your wrapper, so it takes the theme of `:root`
  / `body`, for base colors as well.
- **Override a derived token at any scope** only if you want a different shade:
  `.my-theme { --color-rop-primary-hover: #123456; }` wins over the computed one. Like any custom
  property it is inherited: a nested theme clears it with `--color-rop-primary-hover: initial`.
- **Do not read a derived token with a bare `var()`**: the name is an optional override, unset by
  default, so `var(--color-rop-primary-hover)` resolves to nothing. To use the shade in your own CSS,
  keep the override and the formula together, **on the element**:

  ```css
  .my-link:hover {
    color: var(--color-rop-primary-hover, color-mix(in srgb, var(--color-rop-primary) 80%, black));
  }
  ```

  In Tailwind mode (b) use the utility (`bg-rop-primary-hover`) or `--theme(--color-rop-primary-hover)`,
  which compiles to the same thing (`--theme(... inline)` gives the bare formula, which ignores an
  override).
- **Do not declare that formula on `:root`** in your own variable: it is computed there and inherited
  as a finished colour, so a base color redeclared on a wrapper would not reach it.
- **An alias of a derived token needs a value**: with `primary-hover` unset,
  `--color-rop-primary-active: var(--color-rop-primary-hover)` is ignored in silence and the computed
  shade stays. Write the color, or the full recipe above.

Two more limits at wrapper scope. `--color-rop-blue-600` does not move `--color-rop-primary`: the
primary is resolved on `:root`, redeclare it directly. The row selection and the count flash of the
List Report are drawn with the `blue` scale, so they stay blue with any theme, on `:root` as well
([#293](https://github.com/Utumno1984/react-object-page/issues/293)).

## `cn()`

```ts
import { cn } from '@react-object-page/core';

cn('px-2', 'px-4'); // 'px-4'
cn('z-rop-modal', 'z-rop-popover'); // 'z-rop-popover'
cn('text-rop-body', 'text-rop-error'); // both kept: a size and a color
cn('hover:px-2', cond && 'hover:px-4', { 'font-rop-mono': isCode }); // clsx syntax
```

`cn()` merges conflicting Tailwind classes (last one wins) and knows the library tokens: the
list is read from the same `tokens.css` that produces `theme.css`, so it cannot drift.
